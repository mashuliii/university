# Работа с проектом на компьютере в аудитории

## Общая схема

Каждое занятие строится по одному принципу:

```text
GitHub
   ↓
клонирование проекта
   ↓
VS Code
   ↓
Docker → PostgreSQL
   ↓
выполнение работы
   ↓
Git commit + push
   ↓
GitHub
   ↓
удаление локальной среды
```

Главное правило:

> Единственным постоянным местом хранения вашей работы является ваш GitHub-репозиторий.

Файлы на компьютере в аудитории и данные внутри Docker рассматриваются как временные.

---

# 1. Начало занятия

## Шаг 1. Создайте временную рабочую папку

Например:

```text
D:\students\
```

или другую папку, указанную преподавателем.

Не работайте непосредственно с рабочего стола или внутри чужой папки проекта.

---

## Шаг 2. Откройте VS Code

Откройте встроенный терминал:

```text
Terminal -> New Terminal
```

Убедитесь, что установлен Git:

```powershell
git --version
```

Убедитесь, что работает Docker:

```powershell
docker --version
```

---

## Шаг 3. Склонируйте свой проект с GitHub

Перейдите в рабочую папку, например:
```
cd D:\students
```

Клонируйте свой репозиторий:

```powershell
git clone https://github.com/USERNAME/REPOSITORY.git
```

Например:

```powershell
git clone https://github.com/student123/database-course.git
```

Перейдите в папку проекта:

```powershell
cd database-course
```

Откройте её в VS Code

---

# 2. Проверьте состояние Git

Перед началом работы обязательно выполните:

```powershell
git status
```

Затем получите последние изменения из GitHub:

```powershell
git pull
```

Это особенно важно, если на прошлом занятии вы работали на другом компьютере.

Рабочая последовательность всегда должна начинаться так:

```text
git clone
    или
git pull
      ↓
только потом работа
```

---

# 3. Запустите PostgreSQL

В проекте должен находиться файл:

```text
compose.yaml
```

Например:

```yaml
name: postgres-study

services:
  postgres:
    image: postgres:16
    container_name: pg16_check

    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: postgres

    ports:
      - "5432:5432"

    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

Запустите PostgreSQL:

```powershell
docker compose up -d
```

Проверьте:

```powershell
docker ps
```

Контейнер должен иметь состояние:

```text
Up
```

---

# 4. Подключитесь через DBeaver

Используйте параметры:

```text
Host:       127.0.0.1
Port:       5432
Database:   postgres
Username:   postgres
Password:   postgres
```

При работе на общем компьютере рекомендуется **не сохранять личные пароли и учётные данные** в DBeaver.

Для учебного локального PostgreSQL пароль `postgres` является частью учебного окружения и не является вашим личным паролем.

---

# 5. Выполняйте работу

Все файлы, которые являются результатом работы, должны находиться **внутри Git-репозитория**.

Например:

```text
database-course/
│
├── compose.yaml
│
├── README.md
│
├── seminar1/
│   ├── queries.sql
│   ├── homework.md
│   └── schema.sql
│
└── homework/
    └── homework1.sql
```

Не храните важные результаты только внутри PostgreSQL.

Например, если вы создали таблицу вручную в DBeaver, SQL-код её создания необходимо сохранить в файл:

```text
schema.sql
```

Если написали запрос:

```sql
SELECT *
FROM projects;
```

он также должен быть сохранён в `.sql`-файле.

Принцип:

```text
PostgreSQL содержит результат выполнения SQL

Git содержит сам SQL-код
```

Именно Git позволяет продолжить работу на другом компьютере.

---

# 6. В течение занятия периодически сохраняйте работу в Git

Проверить изменения:

```powershell
git status
```

Добавить изменения:

```powershell
git add .
```

Создать сохранение:

```powershell
git commit -m "Выполнено задание семинара 1"
```

Отправить на GitHub:

```powershell
git push
```

Не обязательно ждать конца занятия. Желательно делать `commit` после завершения логического этапа работы.

Например:

```text
commit 1 — создана ER-модель
commit 2 — создан SQL-скрипт
commit 3 — выполнены запросы
```

---

# 7. Завершение занятия

Перед удалением проекта обязательно убедитесь, что вся работа находится на GitHub.

## Шаг 1. Проверьте Git

Выполните:

```powershell
git status
```

Если есть изменённые или новые файлы:

```powershell
git add .
git commit -m "Работа на занятии завершена"
git push
```

После этого снова:

```powershell
git status
```

Желательный результат:

```text
nothing to commit, working tree clean
```

---

## Шаг 2. Проверьте отправку в GitHub

Убедитесь, что команда:

```powershell
git push
```

завершилась без ошибки.

При возможности откройте свой репозиторий GitHub и убедитесь, что последний commit появился.

Только после этого разрешается удалять локальные файлы.

---

# 8. Остановите и удалите PostgreSQL студента

Перейдите в папку проекта и выполните:

```powershell
docker compose down -v
```

Команда удалит:

- контейнер PostgreSQL;
- сеть Docker проекта;
- Docker volume с учебной базой данных.

То есть данные PostgreSQL этого занятия будут удалены.

Проверить можно командой:

```powershell
docker ps -a
```

Вашего учебного контейнера там быть не должно.

Важно: обычная команда

```powershell
docker compose down
```

не удаляет volume с базой данных.

Поэтому на компьютере в аудитории используется:

```powershell
docker compose down -v
```

---

# 9. Не удаляйте общий образ PostgreSQL

Команда:

```powershell
docker compose down -v
```

удаляет вашу рабочую среду, но оставляет образ:

```text
postgres:16
```

Это нормально.

Не нужно выполнять:

```powershell
docker rmi postgres:16
```

Образ PostgreSQL не содержит вашей базы данных и может использоваться следующим студентом.

Это позволяет не скачивать PostgreSQL из интернета на каждом занятии.

---

# 10. Удалите локальный Git-репозиторий

Сначала выйдите из папки проекта:

```powershell
cd ..
```

Затем удалите папку своего репозитория.

Например:

```powershell
Remove-Item -Recurse -Force .\database-course
```

Либо удалите папку через Проводник Windows.

После этого на компьютере не должно оставаться локальной копии вашей работы.

---

# 11. Удалите своё подключение из DBeaver

Если вы создавали отдельное подключение к PostgreSQL, после занятия его можно удалить:

```text
DBeaver
→ Connections
→ ваше подключение
→ Delete
```

Особенно это важно, если в подключении были сохранены персональные логины или пароли.

---

# 12. Выйдите из GitHub

Если во время занятия выполнялся вход в GitHub через:

- VS Code;
- браузер;
- Git Credential Manager,

перед уходом необходимо выйти из своей учётной записи.

В VS Code проверьте меню учётной записи в левом нижнем углу и выполните выход из GitHub.

Если GitHub открывался в браузере, также завершите сеанс или используйте приватное окно браузера.

На общем компьютере нельзя оставлять сохранённую авторизацию GitHub.

---

# 13. Итоговая проверка перед уходом

Перед завершением занятия студент должен проверить:

```text
☐ git status показывает чистое состояние

☐ git push выполнен успешно

☐ последний commit находится на GitHub

☐ docker compose down -v выполнен

☐ контейнер PostgreSQL удалён

☐ Docker volume проекта удалён

☐ локальная папка репозитория удалена

☐ подключение DBeaver удалено при необходимости

☐ выполнен выход из GitHub

☐ в браузере не осталась открытая личная учётная запись
```

# Короткая памятка

## В начале занятия

```powershell
cd D:\students

git clone https://github.com/USERNAME/REPOSITORY.git

cd REPOSITORY

git pull

docker compose up -d

docker ps
```

Работаем в:

```text
VS Code + DBeaver
```

---

## В конце занятия

Сначала сохранить:

```powershell
git status
git add .
git commit -m "Работа на занятии"
git push
```

Затем удалить рабочую среду:

```powershell
docker compose down -v
```

Выйти из папки:

```powershell
cd ..
```

Удалить локальный репозиторий:

```powershell
Remove-Item -Recurse -Force .\REPOSITORY
```

И обязательно выйти из GitHub.

# Главное правило

```text
Начало занятия:

GitHub
   ↓
git clone / git pull
   ↓
локальная работа


Конец занятия:

локальная работа
   ↓
git add
   ↓
git commit
   ↓
git push
   ↓
GitHub
   ↓
docker compose down -v
   ↓
удаление локального проекта
```

**Сначала `push`, только потом удаление.**
